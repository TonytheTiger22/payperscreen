Paying per check, in plain words

Most data services want a contract, a monthly plan and an API key to look after. We use x402, an open payment standard that lets software pay for a web request at the moment it makes it. Think of a vending machine for data.

  1. 1

    Your system asks

    It sends a name, wallet, email or IP address to our address, like any other web request.

  2. 2

    We name the price

    Instead of the answer, the first reply says what the check costs: 2 cents in USDC.

  3. 3

    Your wallet pays

    Your system signs a 2 cent payment from its own wallet. No card, no invoice, no gas fee.

  4. 4

    You get the result

    In a couple of seconds, with a record of which lists were checked and when.

$1

What's USDC? A digital dollar: 1 USDC is worth 1 US dollar. You load a wallet once and your software spends from it, a few cents at a time. Libraries for x402 handle steps 2 and 3 automatically, so to your code it's one call.

Ask a developer to plug it in

About ten lines with the open-source x402 library. Your system keeps a wallet with a few dollars of USDC and pays per call.

import { wrapFetchWithPayment } from "@x402/fetch";

// client = an x402 client holding your wallet
const pay = wrapFetchWithPayment(fetch, client);

const res = await pay(
  "https://api.payperscreen.com/screen?name=Jane%20Doe");
const { hitCount, hits } = await res.json();

if (hitCount > 0) sendToReview(hits);

Full working script: agent-client.mjs. Every endpoint and response: API docs.

What a check is, and what it isn't

We give you the facts: which lists were checked, what matched and how closely. We don't make the compliance decision for you, and we're not a replacement for your own policy. Every signal we use is listed in public, and so is the age of every list.
